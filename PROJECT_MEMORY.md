# InduCore Project Memory (`PROJECT_MEMORY.md`)

This document serves as the single source of truth for all architectural decisions, domain models, technical stacks, conventions, and operational rules governing the **InduCore** platform. All engineering agents and human contributors MUST adhere strictly to this project memory.

---

## 1. Vision

To empower global industrial manufacturers, energy producers, and enterprise supply chain networks with a resilient, multi-tenant, real-time resource planning and operational intelligence platform that bridges plant-floor IoT telemetry with executive procurement workflows.

---

## 2. Mission

Deliver a secure, cloud-native enterprise application suite built on Clean Architecture and Domain-Driven Design (DDD) principles that ensures zero-trust multi-tenancy, deterministic domain invariant enforcement, event-driven auditing, and AI-assisted procurement decision-making.

---

## 3. Business Goals

- **Procurement Efficiency**: Reduce RFQ processing and bid scoring lead time from days to minutes using automated Gemini AI bid analysis.
- **Operational Resiliency**: Prevent plant-floor downtime by correlating real-time IoT telemetry thresholds with preventive spare part replenishment RFQs.
- **Zero-Trust Multi-Tenancy**: Ensure 100% strict data isolation between enterprise tenants via Row-Level Security (RLS) and context-injected tenant headers.
- **Immutable Governance**: Guarantee ISO/IEC 27001 and SOC 2 Type II auditability via an append-only Transactional Outbox domain event ledger.

---

## 4. Architecture

InduCore follows **Clean Architecture**, **Domain-Driven Design (DDD)**, and an **Event-Driven Outbox Pattern**:

```
[ Presentation / API Layer ]  --->  Apps (`apps/api-gateway`, `apps/web-portal`)
           |
[ Application Layer ]         --->  Use Cases, DTOs, Ports (`packages/application`)
           |
[ Core Domain Layer ]         --->  Pure Entities, Aggregates, Value Objects (`packages/core-domain`)
           ^
[ Infrastructure Layer ]      --->  DB, Messaging, Gemini SDK (`packages/infrastructure`)
```

### Architectural Principles & Invariants
1. **Domain Isolation**: `packages/core-domain` has **zero external npm dependencies** (except pure math/type utilities).
2. **Dependency Inversion**: High-level application modules depend on abstract port interfaces (`IRFQRepository`, `IEventOutboxPublisher`), never on concrete drivers.
3. **Transactional Outbox Pattern**: All domain events generated by Aggregate Root operations are recorded and published asynchronously via an Outbox worker to guarantee at-least-once message delivery.
4. **Strict Type Safety**: Zero usage of `any` or loose type assertions. All runtime inputs validated using `zod` schemas.
5. **Server-Side AI SDK**: All Google Gemini API integrations reside exclusively in backend infrastructure services (`GeminiAIService`), using `@google/genai`.

## 6. Terminology (Ubiquitous Language)

- **Tenant**: An isolated corporate organization operating within the InduCore platform (`TenantId`).
- **RFQ (Request for Quotation)**: A formal procurement specification issued by a tenant listing requested line items (`RFQAggregate`).
- **Line Item**: A specific part or material requested within an RFQ (`RFQLineItem`), defined by SKU and required quantity.
- **Supplier Bid**: A competitive proposal submitted by an industrial vendor specifying bid amount, lead time, and terms (`SupplierBid`).
- **Bid Score**: A calculated or AI-generated rating (0–100) evaluating a supplier bid against RFQ requirements (`EvaluateBidsWithAIUseCase`).
- **Outbox Relayer**: A background consumer process that reads queued domain events and publishes them to messaging topics.
- **Sensor Telemetry**: Real-time operational readings (vibration, temperature, pressure) emitted by plant-floor equipment.

## 10. Permission & Security Model

- **Tenant Isolation**: Every incoming HTTP request must include `X-Tenant-ID` header, validated by `tenantContextMiddleware`.
- **Role-Based Access Control (RBAC)**:
  - `PLANT_MANAGER`: Full access to equipment telemetry, view RFQs.
  - `PROCUREMENT_OFFICER`: Author and publish RFQs, initiate AI bid evaluations.
  - `SUPPLIER_REPRESENTATIVE`: Submit bids against published RFQs.
  - `AUDITOR`: View immutable audit trail and ISO compliance logs.
- **Zero-Trust Principles**: Database queries filter by `tenant_id` at all layers. Secrets remain isolated in `.env.example` placeholders.

---

## 11. Events

- `RFQCreatedEvent`: Fired when an RFQ is created and published.
  - *Attributes*: `rfqId: string`, `tenantId: string`, `dateTimeOccurred: Date`.
- `BidSubmittedEvent`: Fired when a supplier submits a competitive bid.
  - *Attributes*: `rfqId: string`, `supplierId: string`, `bidAmount: number`, `dateTimeOccurred: Date`.
- `BidEvaluatedEvent`: Fired when AI scoring is applied to bids on an RFQ.
  - *Attributes*: `rfqId: string`, `evaluationsCount: number`, `dateTimeOccurred: Date`.

---

## 12. Entities & Aggregates

- **`RFQAggregate`** (Aggregate Root): Encapsulates title, description, status (`RFQStatus`), collection of line items, and supplier bids.
- **`RFQLineItem`** (Entity): Represents a part item requested (SKU, part name, quantity, target price).
- **`SupplierBid`** (Entity): Represents a vendor proposal (supplier ID, name, total amount, lead time, AI score).
- **`Money`** (Value Object): Represents currency amount and 3-letter currency code (`USD`).
- **`TenantId`** (Value Object): Immutable unique identifier for an enterprise tenant.

---

## 13. Entity Relationships

```
TenantId (VO) <1---*> RFQAggregate (Root)
                             |
                             |--- 1:* ---> RFQLineItem (Entity) [Money VO]
                             |
                             |--- 0:* ---> SupplierBid (Entity) [Money VO]
```

- Each `RFQAggregate` belongs to exactly 1 `TenantId`.
- Each `RFQAggregate` contains 1 or more `RFQLineItem` entities.
- Each `RFQAggregate` contains 0 or more `SupplierBid` entities submitted by vendors.
- `Money` value objects represent monetary values inside line items and supplier bids.
